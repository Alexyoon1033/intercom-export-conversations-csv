Security & Zero-Data Architecture Factsheet

Product: ChatVault: Conversation Transcript & CSV Exporter (for Intercom) · Version 1.2.0 · Document Date: Nov 2026
GDPR / CCPA Executive Summary for InfoSec & Procurement Teams:
ChatVault is a 100% client-side, zero-backend browser utility. It runs strictly inside the employee's local Chromium browser and streams exported transcripts directly to the user's local hard drive via FileSystemWritableFileStream. Because the vendor operates zero backend servers and never receives, stores, proxies, or accesses any Intercom tokens or customer PII, ChatVault does not act as a Data Processor or Sub-processor under GDPR Art. 28 or CCPA.

1. Technical Architecture & Network Boundaries (Enforced by Chrome MV3 Sandbox)

Chrome Extension Permissions ["storage"] only (1 minimal permission; no tabs, activeTab, scripting, cookies, or <all_urls>).
Allowed Host Permissions (Strict Egress Allowlist) https://api.intercom.io/* (US Workspace API)
https://api.eu.intercom.io/* (EU Workspace API)
https://api.au.intercom.io/* (AU Workspace API)
https://api.gumroad.com/* (License Key Verification Only)
The Chromium MV3 sandbox structurally blocks outbound requests to any other domain.
Vendor Backend / Telemetry Servers None (0 bytes transmitted). No analytics SDKs, no crash reporters, no remote code execution.
Intercom Token Scope Required Read-Only Internal Integration Token (Read conversations, Read contacts, Read admins). All write scopes remain unchecked. Token stays in volatile browser memory and is never persisted to remote servers.
Local Persistence Only pagination checkpoints (IndexedDB) and license verification timestamp (chrome.storage.local), both clearable in one click inside the workstation UI.
Open Auditability Full unminified ES Module source code is publicly auditable at github.com/Alexyoon1033/intercom-export-conversations-csv.

2. Data Flow Verification (Zero Intermediaries)

  • Step 1 (Read): Employee's browser sends authenticated HTTPS GET/POST requests directly to official Intercom regional API gateways (Intercom-Version: 2.11).
  • Step 2 (Transform): HTML stripping, Excel UTF-8 BOM formatting, 32,000-character cell protection, and optional ZIP packaging occur locally in the employee's browser RAM (<30 MB ceiling via 50-chat disk flushes).
  • Step 3 (Write): Clean .csv, .jsonl, .md, or .zip output is written directly to the employee's local corporate disk.
