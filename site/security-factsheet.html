Security & Data Flow Factsheet

Product: ChatVault: Conversation Transcript & CSV Exporter (for Intercom) · Release notes for 1.2.1 · Document Date: Nov 2026
Browser data flow for security and procurement review
ChatVault processes transcripts in Chromium and writes them locally. Authenticated export requests go directly to Intercom. Gumroad handles purchases and license verification. Review these data flows under your organization’s security and privacy requirements.

1. Technical Architecture & Network Boundaries (Enforced by Chrome MV3 Sandbox)

Chrome Extension Permissions ["storage"] only (1 minimal permission; no tabs, activeTab, scripting, cookies, or <all_urls>).
Declared Extension Host Permissions https://api.intercom.io/* (US Workspace API)
https://api.eu.intercom.io/* (EU Workspace API)
https://api.au.intercom.io/* (AU Workspace API)
https://api.gumroad.com/* (License Key Verification Only)
These permissions describe privileged extension access. Optional attachment retrieval can contact the host of an attachment URL.
Vendor Backend / Telemetry Servers Developer-operated transcript ingestion and analytics are absent from the exporter. The public website is hosted on Cloudflare Pages.
Intercom Token Scope Required Read-Only Internal Integration Token for the authorized workspace. Enable conversation read access for export and contact read access if using contact enrichment. The browser sends the token directly to Intercom.
Local Persistence Pagination and completed IDs are stored in IndexedDB. The key, purchase email, sale ID and verification timestamps are cached locally. The workstation lets the user clear each.
Open Auditability Full unminified ES Module source code is publicly auditable at github.com/Alexyoon1033/intercom-export-conversations-csv.

2. Data Flow Verification (Zero Intermediaries)

  • Step 1 (Read): Employee's browser sends authenticated HTTPS GET/POST requests directly to official Intercom regional API gateways (Intercom-Version: 2.11).
  • Step 2 (Transform): HTML stripping, Excel UTF-8 BOM formatting, 32,000-character cell protection, and optional ZIP packaging occur locally in the employee's browser. ZIP output buffers content in memory.
  • Step 3 (Write): Clean .csv, .jsonl, .md, or .zip output is written directly to the employee's local corporate disk.
