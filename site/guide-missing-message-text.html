Why Intercom CSV export is missing message text, and how to stream full transcripts locally

When teams export conversations from Intercom's reporting dashboard for compliance archives, helpdesk migrations, or RAG datasets, the downloaded CSV only contains ticket metadata columns (conversation ID, timestamps, assignee, tag names, and SLA timers). It omits the customer messages, agent replies, and internal teammate notes.

1. Why the list endpoint omits conversation threads

In Intercom REST API v2.11, listing conversations via GET /conversations?per_page=150 returns summary objects that only include the initial opening body. The full message thread (conversation_parts.conversation_parts, up to 500 parts per ticket) is a nested resource returned only when you request each conversation ID individually:

GET https://api.intercom.io/conversations?per_page=150&starting_after={cursor}
Headers:
  Authorization: Bearer <READ_ONLY_TOKEN>
  Intercom-Version: 2.11

# For each conversation.id in page.conversations (N+1 detail fetch):
GET https://api.intercom.io/conversations/{id}?display_as=html

2. Four failure modes on 10,000+ conversation exports

  • Rate-limit windows (HTTP 429). Because every page of 150 conversations requires 150 detail calls, scripts hit HTTP 429 unless they inspect X-RateLimit-Remaining (throttling below 20 remaining calls) and pause until the X-RateLimit-Reset UNIX epoch timestamp.
  • Regional API gateways. EU and AU workspaces return 401 Unauthorized if queried against api.intercom.io instead of api.eu.intercom.io or api.au.intercom.io.
  • Browser V8 heap crashes (OOM). Concatenating 30,000+ HTML transcripts into one JavaScript string or Blob exceeds V8's UTF-16 string heap limit (~500 MB) and terminates the tab.
  • Excel UTF-8 and 32,767-character cell overflow. Raw HTML tags (<p>, <br>) and email threads exceeding 32,767 characters corrupt rows in Microsoft Excel unless sanitized, truncated at 32,000 characters, and prefixed with a UTF-8 BOM (\uFEFF).

3. Streaming directly to disk in a dedicated browser tab

ChatVault runs inside a dedicated browser tab using FileSystemWritableFileStream and 50-conversation IndexedDB checkpoints:

  • Flushes every 50 conversations directly to disk so browser RAM stays under 30 MB across 250,000 conversations.
